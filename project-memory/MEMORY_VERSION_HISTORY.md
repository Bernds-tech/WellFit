# WellFit Project Memory Version History

## V1–V3 — Existing baseline
Initial operational memory, task/open-loop/dependency/evidence/decision controls, cross-project registry, stale scan and execution/countercheck foundations.

## V4 — Execution continuity
Adds `STARTED_WORK.md`, `WORK_LOCKS.md`, `EXECUTION_RECEIPTS.md` and `RECONCILIATION.md`. Substantive work must remain visible across sessions and cannot be silently restarted.

## V5 — Quality and falsification
Adds `QUALITY_CONTROL.md` and formalizes R1–R4 risk, assumptions/contradictions, independent countercheck, evidence quorum, rollback/recovery expectations and falsification questions.

## V6 — Finishline and external acceptance
Adds human/machine finishline controls, `EXTERNAL_ACCEPTANCE.md`, derived next-action discipline and fail-closed acceptance rules. Repository implementation cannot self-approve external visual/product acceptance.

## V7 — Freshness, drift, milestones and governance
Adds explicit evidence TTL, accepted-state drift baseline, append-only milestone snapshots and branch-protection contract. Stale mutable evidence cannot support fresh acceptance.

## V8 — Cross-chat, impact, owner inbox, auto-handoff and convergence
Adds cross-chat reconciliation, impact matrix, compact owner-action inbox, automatic handoff, next-best-action operation and the three-repository convergence plan.

Current version: **V8**.
