# Project Memory Protocol v1

Operational memory for the WellFit visual/landing/UI repository.

## Mandatory preflight
Read `CURRENT_STATE.md`, `TASK_LEDGER.md`, `DECISIONS.md`, `FAILED_ATTEMPTS.md` and `CHANGE_REQUESTS.md`; then inspect current branch, git status and recent commits/PRs. Search for an existing task/change ID and prior attempt before starting new work.

## Mandatory postflight
After meaningful work, update task/state history; record decisions, failed approaches and new owner ideas. Never silently expand scope.

## Status vocabulary
`TODO`, `IN_PROGRESS`, `BLOCKED`, `PARTIAL`, `DONE`, `REJECTED`, `SUPERSEDED`, `DEFERRED`, `DUPLICATE`.

## Change intake
New ideas first enter `CHANGE_REQUESTS.md`, then become an existing-task subtask, new accepted task, deferred item, rejected item or duplicate. Later scope must not be rewritten into old completed work.

## Evidence
For each attempt record ID, date, goal, starting state, action, result, failure/cause, decision, evidence/commit/PR, next step and do-not-repeat guidance.

Never store secrets, tokens, credentials or private user data here.
